# 학생 증거 AI 제공자 연결 규약

Mumu 평가는 OCR·음성 전사·평가 챗봇·루브릭 추천을 특정 회사 API에 고정하지 않습니다. 서버의 `EvidenceAiProvider` 인터페이스를 구현하고 레지스트리에 등록하면 같은 개인정보 게이트, 실행 이력, 오류 처리, 교사 최종 판단 흐름을 재사용할 수 있습니다.

## 외부 전송 게이트

외부 호출은 다음 조건을 모두 만족할 때만 실행됩니다.

1. 교사가 로그인했고 승인 계정 목록에 포함되어야 합니다.
2. 교사의 `학생 증거 AI 안전 설정`에서 학교 승인 스위치가 켜져 있어야 합니다.
3. 등록된 외부 AI 제공자가 선택되어 있어야 합니다.
4. 사진·녹음은 학생이 이름·번호가 포함되지 않았음을 확인해야 합니다.
5. 텍스트·챗봇·루브릭 추천은 알려진 학생 이름·참조 번호를 서버에서 다시 마스킹합니다.
6. 제공자에는 학생 DB ID 대신 단방향 익명 해시만 전달합니다.
7. 실행 ID·기능·모델·프롬프트 버전·입력 해시를 외부 호출 전에 저장하고, 성공·실패·토큰·지연 시간을 나중에 기록합니다.

설정은 기본적으로 꺼져 있습니다. API 경로를 직접 호출해도 서버가 같은 조건을 다시 확인합니다.

## 기능별 전송 범위

| 기능 | 외부 제공자에 보내는 내용 | 보내지 않는 내용 |
|---|---|---|
| 손글씨 OCR | 식별정보가 없다고 확인한 답안 사진, 문항, 학습 목표, 익명 해시 | 학생 이름·번호, 교사 계정, Blob 경로 |
| 음성 전사 | 식별정보가 없다고 확인한 음성 원본, 익명 해시 | 학생 이름·번호, 교사 계정, 저장 경로 |
| 평가 챗봇 | 식별정보를 마스킹한 대화, 문항, 학습 목표, 익명 해시 | 명렬 정보, 실제 학생 ID |
| 루브릭 추천 | 식별정보를 마스킹한 해당 평가 요소의 학생 증거, 성취기준, 상·중·하 기술문, 도움 수준, 익명 해시 | 학생 이름·번호, 교사 최종 판단 권한 |

AI 추천은 `상·중·하·판단 보류`, 근거 인용, 불확실성, 부족한 증거, 평가 구성개념 유의점을 반환합니다. 교사가 원문과 루브릭을 보고 별도로 최종 확정합니다. OCR·전사 결과는 교사가 원본과 대조해 확인본을 저장하기 전에는 추천 평가에 사용하지 않습니다.

## 새 제공자 추가

1. `lib/evidence-ai/provider.ts`의 `EvidenceAiProvider`를 구현합니다.
2. OCR·전사·챗봇·루브릭 추천 중 실제 지원하는 capability만 선언합니다.
3. 각 메서드는 공통 `ProviderResult`로 구조화 결과·모델·사용량·제공자 메타데이터를 반환합니다.
4. 서버 전용 모듈에서 `registerEvidenceAiProvider("provider-id", factory)`로 등록합니다.
5. `lib/evidence-ai/index.ts`에서 등록 모듈을 불러옵니다.
6. API 키는 서버 환경변수로만 관리하고 클라이언트 번들·DB·로그에 저장하지 않습니다.
7. 실패를 `EvidenceAiError`로 변환하고 402·403·429·503을 구분합니다.
8. 합성 사진·합성 음성·합성 대화로 게이트와 결과 스키마를 검증한 뒤 운영 선택지에 노출합니다.

현재 기본 구현은 `vercel-gateway`이며 모델은 기능별 환경변수로 분리할 수 있습니다. 다른 제공자를 추가해도 교사 정책에 저장된 provider ID가 요청마다 전달되므로, 한 학교 설정에서 승인하지 않은 제공자로 자동 전환하지 않습니다.

## 저장과 보존

원본 사진·음성은 private Vercel Blob에 두고, DB에는 익명 경로·형식·크기·SHA-256·식별정보 제거 확인·보존 기한만 저장합니다. 브라우저에서 원본을 볼 때도 학생 참여 쿠키 또는 교사 소유권을 다시 검사합니다.

현재 보존 기한은 메타데이터로 기록됩니다. 운영 자동 삭제 작업과 백업 삭제 정책은 학교 정책 확정 후 별도 배포·검증해야 합니다.

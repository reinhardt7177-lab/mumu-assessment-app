# Mumu 평가 운영 전환 현황

최종 확인: 2026-08-31. 목표는 초등 교사가 성취기준 기반 평가를 만들고 QR로 배포한 뒤, 글·사진·음성·챗봇 답안을 수합해 AI 평가 초안을 검토·확정하는 실제 운영 앱이다.

## 현재 코드와 운영 상태는 다르다

| 범위 | 코드 상태 | 확인한 증거 / 남은 검증 |
| --- | --- | --- |
| 초등 성취기준 | 국어·사회·수학·과학·도덕·영어 423개 | PDF 추출 보고서 `data/achievement-standards.2022.md`, 중복 0 |
| 평가 생성 | 6단계, 성취기준·문항·루브릭·교사 설정 상중하 기준 | 서버 검증 및 DB 테스트 |
| 교사 로그인 | Clerk + 승인된 교사 ID만 허용 | 실제 Clerk 앱·키·교사 승인 연결 필요 |
| 영구 저장 | Neon Postgres SQL, 서버 전용 연결 | 운영 `DATABASE_URL` 미설정. 실제 운영 DB에는 아직 아무 자료도 저장하지 않음 |
| 고유 QR·학생 시험지 | 평가별 URL, 교사 메뉴 없음 | 실제 로그인→배포 브라우저 흐름 미검증 |
| 글 답안 | 서버 자동 저장, 충돌 검사, 최종 제출 잠금, 재시도 중복 방지 | PGlite PostgreSQL 테스트 통과. 실배포 세션·통신 검증 필요 |
| 교사 채점·결과 | 원문·문항별 점수·근거·피드백, 확정/공개 분리, 변경 이력 | DB 테스트 통과. 브라우저 검증 필요 |
| 학생 결과 | 자기 참여 토큰으로 공개된 결과만 읽기 | DB 권한 테스트 통과 |
| CSV | 교사만 조회한 결과 내려받기, 수식 주입 방어 | 실제 다운로드 검증 필요 |
| Luna 문항 생성 | 실제 Gateway API, 승인 교사만 호출, 원본 성취기준으로 프롬프트 구성 | Gateway 유료 크레딧 제한. 성공 출력 검증 미완료 |
| OCR·음성·대화·AI 채점 | 아직 미완성 | 실제 배포 UI에서 비활성화. 데모는 `/demo`로 분리 |

## 저장·접근 원칙

- 서버 DB가 유일한 기준이다. localStorage나 메모리 저장소로 운영 DB 실패를 대체하지 않는다.
- 담당 교사 소유권을 모든 조회·쓰기 SQL에서 확인한다. 로그인만으로 다른 교사의 데이터에 접근할 수 없다.
- 학생은 번호/별칭과 256비트 임의 참여 토큰을 사용한다. 토큰 원문은 HttpOnly·SameSite 쿠키에만, DB에는 SHA-256 해시만 남긴다.
- 번호/별칭은 실명 인증이 아니다. 운영 전 명부 확인·대리 응시 방지 방식이 더 필요하다.
- 학생 쿠키는 이 기기에 연결된다. 공용 기기 전환과 분실 시 교사 주도 복구 흐름은 아직 추가해야 한다.
- 학생 답안과 비공개 결과 응답은 `private, no-store`. 브라우저 성공 표시는 서버 응답 이후에만 띄운다.
- Luna 문항 생성은 승인 교사별 기본 시간당 30회로 DB에서 제한한다. 여러 서버 인스턴스에서도 공유하며 `AI_QUESTIONS_PER_HOUR`로 조정한다. 전체 학생 API 속도 제한과 금액 기준 예산은 별도로 추가해야 한다.
- 문항·루브릭은 공개 후 잠근다. 채점 공개 전에 교사 최종 확정을 요구하고 감사 이력을 남긴다.
- 상/중/하 환산점은 교사 설정값이며 국가 교육과정의 공식 고정 임계점이라고 표현하지 않는다. 등수는 산출하지 않는다.
- 테스트용 PGlite는 테스트 코드에서만 사용한다. 운영 시 로컬 파일/메모리 fallback은 없다.

## 운영 연결 순서

1. 기존 Vercel 프로젝트 `mumu-assessment-app` 연결 확인.
2. Neon 연결 약관을 사용자가 승인하고 DB 준비. 개발/미리보기에는 운영 학생 DB와 분리된 환경 사용.
3. Clerk 앱 연결, `CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` 등록. 교사 계정 ID를 `TEACHER_USER_IDS`에 승인.
4. Vercel 환경변수를 로컬로 pull하고 필수 키 이름만 검증. 비밀값 출력 금지.
5. `npm run db:migrate` 실행. SQL은 `db/migrations`가 기준. 기존 Sites용 `db/schema.ts`와 `db/index.ts`는 운영 Neon 저장소가 아니다.
6. `npm test`, `npm run lint`, `npm run build:vercel`.
7. 실제 교사 로그인 → 평가 생성 → 공개 → 별도 학생 브라우저에서 제출 → 교사 조회/확정/공개 → 학생 결과 확인을 검증.
8. 저장소 백업/복원·보존/삭제 정책, 실제 교육기관 개인정보 처리 조건, 예산·속도 제한을 확정한 뒤 실제 학생 사용.

## 남은 필수 작업

- 실제 DB·Clerk·Luna 연결과 운영 배포 검증.
- 사진/녹음 비공개 파일 저장, OCR/전사 원문 대조·교사 보정.
- 대화 평가 기록과 도움 제공 여부를 구분한 AI 평가.
- AI 추천 수준/근거/불확실성 저장. 교사 확정과 절대 혼합하지 않기.
- 학생 명부/참여 복구/공용 기기 로그아웃, 교사 초안 수정·보관·결과 정정.
- DB 기반 요청 제한·AI 예산 한도, 백업·복원·삭제 검증, 접근 로그와 운영 모니터링.
- 실제 모바일/접근성/키보드/네트워크 단절 UI 검증.

## 의존성 보안 점검

분리된 PostgreSQL 및 HTTP 검증 20개와 ESLint 검사를 통과했다. Next.js 16.3.3 운영 빌드도 확인했다. DB에는 테스트용 가상 학생 번호만 사용했으며 운영 마이그레이션은 실행하지 않았다.

2026-08-31 Next.js 16.3.3으로 업데이트한 뒤 `npm audit --omit=dev`에서 운영 의존성 취약점 0건을 확인했다. 개발 전용 Sites/Cloudflare 도구의 취약점 18건은 별도 정리가 남아 있다. 운영 의존성 점검이 전체 시스템 보안을 보장하지는 않는다.

현재 상태를 ‘완성된 운영 앱’으로 안내하지 않는다. 위 필수 작업과 운영 경계 검증 전 실제 학생 정보를 수집하지 않는다.

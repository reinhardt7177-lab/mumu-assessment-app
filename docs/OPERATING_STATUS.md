# Mumu 평가 운영 전환 현황

최종 확인: 2026-09-01. 목표는 초등 교사가 학기·단원별 성취기준 평가를 만들고, 학생의 수행 증거를 준거 루브릭으로 판단한 뒤 피드백·추가 학습·재평가를 거쳐 학기말 종합 결과까지 만드는 실제 운영 앱이다. QR 배포와 글·사진·음성·챗봇 답안은 그 증거를 수집하는 방법이다.

## 저장·접근 원칙

- 서버 DB가 유일한 기준이다. localStorage나 메모리 저장소로 운영 DB 실패를 대체하지 않는다.
- 학교 교육과정 업로드는 외부 AI로 전송하지 않는다. 서버에서 최대 8MB를 추출한 뒤 원문은 보존하지 않고 파일명·형식·SHA-256 해시·추출 시각·성취기준 수만 출처 기록으로 남긴다. 교사가 검토한 구조화 계획만 승인본이 된다.
- 같은 학교·학년도의 승인본은 버전으로 보존한다. 기존 승인본을 덮어쓰지 않으며, 현재 승인본만 새 학급 계획에 적용할 수 있다.
- 담당 교사 소유권을 모든 조회·쓰기 SQL에서 확인한다. 로그인만으로 다른 교사의 데이터에 접근할 수 없다.
- 학생은 번호/별칭과 256비트 임의 참여 토큰을 사용한다. 토큰 원문은 HttpOnly·SameSite 쿠키에만, DB에는 SHA-256 해시만 남긴다.
- 번호/별칭은 실명 인증이 아니다. 운영 전 명부 확인·대리 응시 방지 방식이 더 필요하다.
- 학생 쿠키는 이 기기에 연결된다. 공용 기기 전환과 분실 시 교사 주도 복구 흐름은 아직 추가해야 한다.
- 학생 답안과 비공개 결과 응답은 `private, no-store`. 브라우저 성공 표시는 서버 응답 이후에만 띄운다.
- Luna 문항 생성은 승인 교사별 기본 시간당 30회로 DB에서 제한한다. 여러 서버 인스턴스에서도 공유하며 `AI_QUESTIONS_PER_HOUR`로 조정한다. 전체 학생 API 속도 제한과 금액 기준 예산은 별도로 추가해야 한다.
- 문항·루브릭은 공개 후 잠근다. 채점 공개 전에 교사 최종 확정을 요구하고 감사 이력을 남긴다.
- 상/중/하 환산점은 교사 설정값이며 국가 교육과정의 공식 고정 임계점이라고 표현하지 않는다. 등수는 산출하지 않는다.
- 테스트용 PGlite는 테스트 코드에서만 사용한다. 운영 시 로컬 파일/메모리 fallback은 없다.

## 운영 연결 순서

1. [완료] 기존 Vercel 프로젝트 `mumu-assessment-app` 연결 확인.
2. [개발 완료] Neon 무료 개발용 저장소 연결 및 로컬 환경 동기화. Production/Preview로 비밀값을 복사하는 작업은 사용자 명시 승인 대기.
3. [진행 중] Clerk 무료 개발용 앱·키 연결 완료. 교사 가입 뒤 해당 ID만 `TEACHER_USER_IDS`에 승인해야 함.
4. [부분 완료] Vercel Development 환경변수와 로컬 필수 키 이름을 검증. Production/Preview에는 아직 Clerk·Neon 키가 없고 `TEACHER_USER_IDS`도 미설정.
5. [개발 완료] `npm run db:migrate`로 `0001_assessment_core.sql`·`0002_curriculum_growth.sql`·`0003_ai_assessment_suggestions.sql`·`0004_assessment_growth_bridge.sql`·`0005_school_curriculum_plans.sql` 적용 및 재실행 체크섬 검증. 기존 Sites용 `db/schema.ts`와 `db/index.ts`는 운영 Neon 저장소가 아니다.
6. `npm test`, `npm run lint`, `npm run build:vercel`.
7. 실제 교사 로그인 → 평가 생성 → 공개 → 별도 학생 브라우저에서 제출 → 교사 조회/확정/공개 → 학생 결과 확인을 검증.
8. 저장소 백업/복원·보존/삭제 정책, 실제 교육기관 개인정보 처리 조건, 예산·속도 제한을 확정한 뒤 실제 학생 사용.

## 남은 필수 작업

- Production/Preview에 Clerk·Neon 환경변수 적용, 교사 회원가입과 `TEACHER_USER_IDS` 승인, 실제 로그인 저장 E2E.
- 실제 학교의 표 형식이 서로 다른 PDF·XLSX 표본으로 가져오기 정확도와 교사 수정 시간을 측정하고, 필요하면 학교별 열 매핑 템플릿을 추가.
- Luna 연결과 실제 문항 생성 성공 출력 검증.
- 학생 수행 원문·OCR·음성 전사를 외부 AI Gateway로 전송할지 학교 개인정보 처리 기준과 명시적 승인을 확정. 승인 전에는 AI 학생 증거 분석 호출을 연결하지 않음.
- 사진/녹음 비공개 파일 저장, OCR/전사 원문 대조·교사 보정.
- 대화 평가 기록과 도움 제공 여부를 구분한 AI 평가.
- 학생 증거 AI 추천 저장 구조·교사 분리 표시는 완료. 승인 후 실제 모델 호출, 재시도·예산 제한, 학교별 활성화 정책 검증.
- 학생 명부/참여 복구/공용 기기 로그아웃, 교사 초안 수정·보관·결과 정정.
- DB 기반 요청 제한·AI 예산 한도, 백업·복원·삭제 검증, 접근 로그와 운영 모니터링.
- 실제 모바일/접근성/키보드/네트워크 단절 UI 검증.

## 의존성 보안 점검

2026-09-01 분리된 PostgreSQL 및 HTTP 검증 29개, ESLint 검사, Next.js 16.3.3 Vercel 운영 빌드를 통과했다. 성장 평가 테스트는 학기→단원→잠긴 루브릭→QR 평가→등록 학생 제출→원본 증거 자동 수합→교사 판단→피드백→추가 학습→독립 재평가→학기말 판단 전체 흐름과 교사 소유권·원본 불변성·중복 방지·독립 증거 규칙, AI 추천 실행·성공·실패 이력, 교사 운영 조회 모델을 검증한다. 학교 계획 테스트는 CSV 추출, 학교 멤버 권한, 승인본 버전 보존, 현재 승인본 제한, 승인본→학급 단원·성취기준 원자 복제를 검증한다. 실제 제공된 사회과 교육과정 PDF는 외부 전송 없이 310,455자와 성취기준 코드 49개를 읽었고 원문은 저장하지 않았다. 문항 생성 테스트는 생성 전 실행 기록, 성공·실패·토큰 사용량, 동일 요청 재사용, 저장 이력 복원과 교사 소유권을 검증한다. 개발용 Neon에는 다섯 마이그레이션을 적용하고 재실행 체크섬을 확인했으며 테스트·학생 데이터는 넣지 않았다. 실제 Clerk 로그인과 브라우저 저장 E2E는 아직 검증하지 않았다.

2026-08-31 Next.js 16.3.3으로 업데이트한 뒤 `npm audit --omit=dev`에서 운영 의존성 취약점 0건을 확인했다. 개발 전용 Sites/Cloudflare 도구의 취약점 18건은 별도 정리가 남아 있다. 운영 의존성 점검이 전체 시스템 보안을 보장하지는 않는다.

현재 상태를 ‘완성된 운영 앱’으로 안내하지 않는다. 위 필수 작업과 운영 경계 검증 전 실제 학생 정보를 수집하지 않는다.

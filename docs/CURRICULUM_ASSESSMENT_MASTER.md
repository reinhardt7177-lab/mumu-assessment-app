# Mumu 교육과정 평가 마스터 설계

## 제품 한 문장

초등 교사가 교육과정이나 차시 수업안을 넣으면 성취기준을 해석해 루브릭과 서술형 평가 초안을 만들고, 교사가 수정·확정한 평가를 글·사진·음성·챗봇으로 수합한 뒤 학생별 피드백·추가 학습·재평가·학기말 성장 리포트까지 연결하는 준거참조 종합 평가 플랫폼이다.

## 평가의 중심 원칙

1. **교육과정에서 시작한다.** 학년·학기·교과·단원·성취기준이 평가와 기록의 상위 구조다.
2. **상·중·하는 석차가 아니라 준거 수준이다.** 학생 간 비교가 아니라 성취기준에서 기대하는 수행과 비교한다.
3. **수준 이름보다 수행 기술문이 먼저다.** 각 수준은 학생의 결과물에서 관찰되는 질적 차이를 구체적으로 설명한다.
4. **한 번의 점수로 확정하지 않는다.** 글, 구술, 관찰, 사진, 대화 등 여러 수행 증거를 기준별로 연결한다.
5. **피드백은 다음 수업으로 이어진다.** 강점, 개념·절차·표현 격차, 우선 과제, 추가 학습을 기록한다.
6. **재평가는 같은 답의 재현이 아니다.** 새로운 맥락에서 도움 없이 수행하는지 확인한다.
7. **학기말 결과는 단순 평균이 아니다.** 최근의 독립 수행, 반복 확인, 맥락 다양성, 상충 증거를 함께 보고 교사가 판단한다.
8. **AI는 추천만 한다.** AI 추천 수준·근거·불확실성과 교사의 최종 판단·수정 이유를 분리해 저장한다.

## 전체 흐름

    학교교육과정·학년교육과정 업로드
      → 교사 검토·학교별 승인본 저장
      → 학급 학기 교육과정 계획 적용
      → 단원·성취기준 선택
      → 성취기준 해석(관찰 지표·선행 요소·오개념)
      → 평가 과제·준거 루브릭 설계
      → 학생 수행 증거 수집
      → 기준별 상·중·하 추천
      → 교사 검토·확정
      → 격차별 피드백·추가 학습
      → 새로운 맥락의 재평가
      → 성장 이력 누적
      → 학기말 성취기준별 종합 판단·서술

## 수업안에서 평가까지의 설계 파이프라인

1. **맥락 입력:** 학교·학년 교육과정, 단원 계획, 차시 수업안, 교사가 직접 적은 학습 목표를 받는다.
2. **성취기준 연결:** 문서에서 학년·교과·단원·성취기준을 추출하고, 자동 연결의 근거 문장과 신뢰도를 표시한다. 교사가 연결을 수정할 수 있다.
3. **역량 풀어쓰기:** 성취기준을 관찰 가능한 행동, 선행 지식·기능, 흔한 오개념, 성공 기준으로 나눈다.
4. **루브릭 초안:** 서로 독립적인 평가 요소와 상·중·하·판단 보류 기술문을 만든다. “잘함/부족함”이 아니라 학생 결과물에 실제 나타나는 질적 차이를 쓴다.
5. **평가지 초안:** 각 루브릭 요소를 드러낼 서술형·선택형·구술형·관찰형 문항과 자료, 예상 답안, 채점 근거, 배점을 만든다.
6. **타당도 검사:** 문항이 성취기준의 내용과 사고 수준을 측정하는지, 읽기·말하기·기기 사용 능력 같은 다른 요인이 점수를 왜곡하지 않는지 검사한다.
7. **교사 편집·승인:** 교사는 문항·루브릭·예시 답안·배점·응답 방식을 직접 수정하고 미리보기한 뒤 버전을 잠근다. AI 초안은 교사 승인 전 학생에게 배포되지 않는다.
8. **학급 배포:** 승인된 평가를 특정 학급 명렬에 QR·링크로 배포하며 학생 화면에는 평가 과제와 제출 기능만 표시한다.

이 파이프라인에서 루브릭이 먼저고 평가지가 다음이다. 문항은 반드시 하나 이상의 성취기준·평가 요소·기대 증거에 연결되어야 한다.

## 상·중·하 판단 구조

각 성취기준은 하나의 총점이 아니라 독립된 평가 요소로 나눈다.

| 수준 | 의미 | 기술 방식 |
| --- | --- | --- |
| 상 | 목표 수행을 독립적으로 연결·적용함 | 개념, 근거, 이유, 새로운 맥락의 적용이 결과물에 어떻게 나타나는지 기술 |
| 중 | 목표 수행의 핵심 요소가 나타나지만 연결 또는 적용이 아직 일관되지 않음 | 무엇이 나타났고 어떤 연결이 더 필요한지 기술 |
| 하 | 선행 요소 또는 부분 수행이 나타남 | 현재 확인된 출발점과 다음에 가르칠 한 가지를 기술 |
| 판단 보류 | 관련 독립 증거가 부족하거나 증거가 상충함 | 필요한 추가 증거의 종류와 수집 계획을 기록 |

수준 간 차이를 “많이/조금”, “잘함/부족함”으로 쓰지 않는다. 결과물에 존재하는 행동과 설명의 질적 차이로 쓴다.

## 성장 평가 증거 규칙

모든 수행 증거에는 다음 정보를 붙인다.

- 연결 성취기준과 루브릭 기준
- 단원·과제·문항 맥락
- 응답 방식: 글, 손글씨 OCR, 말하기 전사, 교사 관찰, 챗봇 대화
- 도움 수준: 독립 수행, 교사 질문, 단계 힌트, 예시 제공
- 원본과 변환본, 교사 보정 이력
- 수행 시각, 소요 시간(수준 근거가 아닌 참고 정보)
- AI 추천과 인용 근거
- 교사 확정 수준, 판단 근거, 확정 시각

지원받은 수행은 학습 과정의 중요한 증거지만 독립 수행과 섞지 않는다. 학기말 종합 판단에는 독립 수행 여부를 명시한다.

## 피드백·추가 학습·재평가

학생 답안의 격차는 다음 셋으로 구분한다.

- **개념 격차:** 핵심 개념이나 관계를 다르게 이해함 → 다른 표상과 사례로 다시 가르친다.
- **절차 격차:** 개념은 드러나지만 수행 과정에서 오류가 남음 → 오류가 발생한 단계만 집중 연습한다.
- **표현 격차:** 알고 있으나 근거와 이유를 말이나 글로 나타내지 못함 → 설명 모델과 문장 틀을 제공한다.

피드백 한 사이클은 확인된 강점 → 우선 격차 하나 → 구체적 다음 학습 → 새 맥락 재평가 → 변화 기록으로 저장한다.

## S-W-A-T 학생 성장 프레임

일반 경영 분석의 명칭은 SWOT이지만, 학생 피드백에는 외부의 기회·위협보다 실제 수업 행동이 중요하다. Mumu에서는 다음 교육용 S-W-A-T를 사용한다.

| 구분 | 의미 | 생성 기준 |
| --- | --- | --- |
| S · Strength | 현재 확인된 강점 | 학생 원문·음성·사진·대화에서 루브릭과 일치하는 구체적 근거를 인용 |
| W · Weakness | 아직 연결되지 않은 요소 | 개념·절차·표현 격차로 분류하고 낙인 표현을 사용하지 않음 |
| A · Action | 바로 실행할 학습 행동 | 다음 수업에서 수행할 수 있는 한두 가지 연습, 자료, 교사 지원 |
| T · Target | 다음 독립 수행 목표 | 새 맥락에서 도움 없이 보여 줄 관찰 가능한 성공 기준 |

S-W-A-T은 학생 성향을 단정하는 프로필이 아니라 특정 성취기준과 축적된 수행 증거에 근거한 가변적 학습 계획이다.

## 학기말 종합 판단

시스템은 성취기준마다 다음을 한 화면에 모은다.

- 최초 수행 수준과 가장 최근 독립 수행 수준
- 단원별·방식별 수행 증거 수
- 기준별 수준 변화 타임라인
- 제공된 도움과 추가 학습
- 서로 일치하거나 상충하는 증거
- AI 종합 초안과 불확실성
- 교사가 선택한 핵심 근거
- 최종 상·중·하 또는 판단 보류
- 학생의 성장과 다음 학기 지원을 설명하는 서술

자동 산술 평균으로 수준을 확정하지 않는다. 최신 증거가 이전 증거보다 무조건 우선하는 것도 아니다. 과제가 성취기준을 충분히 대표하는지, 학생이 독립적으로 수행했는지, 여러 상황에서 반복 확인됐는지를 교사가 검토한다.

## 학기말 종합 리포트

학생별 리포트는 점수표 하나가 아니라 다음 네 층으로 구성한다.

1. **현재 위치:** 교과·영역·성취기준별 최종 상·중·하·판단 보류와 교사가 선택한 핵심 증거
2. **성장 과정:** 최초 수행부터 추가 학습·재평가까지의 수준 변화 타임라인과 독립 수행 여부
3. **S-W-A-T 처방:** 강점, 우선 보완점, 구체적 학습 행동, 다음 목표
4. **종합 서술:** 학생·보호자가 이해할 수 있는 성장 설명과 다음 학기 지원 제안

시각화는 성취기준 히트맵, 영역별 분포 막대, 시간에 따른 성장선, 증거 타임라인을 기본으로 한다. 레이더 차트는 축이 충분하고 같은 척도를 사용할 때만 보조적으로 제공한다. 학생 간 등수 그래프는 만들지 않는다.

## AI 에이전트 구성

| 에이전트 | 입력 | 출력 | 교사 통제 |
| --- | --- | --- | --- |
| 교육과정 해석 | 교육과정·수업안·학습 목표 | 성취기준 연결, 관찰 지표, 선행 요소, 오개념 | 연결 근거 확인·수정 |
| 루브릭 설계 | 성취기준 해석과 수업 맥락 | 독립 기준, 수준별 기술문, 학생용 표현 | 기준·수준 편집 후 잠금 |
| 평가지 설계 | 잠금 전 루브릭과 평가 목적 | 문항, 자료, 예상 답안, 배점, 기대 증거 | 전체 편집·삭제·추가 |
| 타당도 감사 | 목표·문항·루브릭·응답 방식 | 정렬 오류, 측정 왜곡, 누락 영역, 수정 제안 | 경고 해소 또는 사유 기록 |
| 증거 변환 | 사진·녹음·챗봇 기록 | OCR·전사·대화 구조화, 변환 신뢰도 | 원본 대조·보정 |
| 준거 분석 | 학생 원본·변환본과 잠금 루브릭 | 기준별 추천 수준, 인용 근거, 불확실성, 격차 유형 | 최종 수준·근거 확정 |
| 성장 리포트 | 확정 판단·피드백·재평가 이력 | S-W-A-T, 성장 시각화, 종합 서술 초안 | 공개 전 최종 승인 |

에이전트끼리 결과를 넘길 때 성취기준 코드, 루브릭 버전, 평가 버전, 모델·프롬프트 버전, 사용한 근거를 함께 저장한다.

## 운영 데이터 모델

assessments 중심 스키마와 다음 교육과정 성장 엔터티를 연결해 운영한다.

| 엔터티 | 핵심 역할 |
| --- | --- |
| schools / school_members | 학교 기본정보와 교사별 학교 접근 권한 |
| school_curriculum_plans | 학교·학년도별 기본사항과 학년·교과 계획 승인 버전 |
| school_curriculum_active_plans | 현재 적용 가능한 학교 승인본 |
| curriculum_terms | 학년도·학기·학년·학급·교과 |
| curriculum_units | 단원 순서·기간·연결 성취기준 |
| standard_targets | 성취기준 해석, 관찰 지표, 선행 요소, 오개념 |
| rubric_versions | 배포 시 잠기는 루브릭 버전 |
| rubric_criteria | 독립 평가 요소와 상·중·하 기술문 |
| assessment_events | 단원 평가, 진단, 재평가의 목적과 맥락 |
| learning_evidence | 학생 원본 수행, 방식, 도움 수준, 연결 기준 |
| criterion_judgements | AI 추천과 교사 확정을 분리한 기준별 판단 |
| feedback_cycles | 강점, 격차 유형, 우선 다음 학습 |
| learning_interventions | 실제 제공한 추가 학습과 학생 반응 |
| reassessment_links | 이전 증거와 재평가 증거의 연결 |
| semester_judgements | 학기말 수준, 선택 근거, 교사 서술, 확정 이력 |

원본 증거와 확정 기록은 덮어쓰지 않는다. 정정은 새 버전과 감사 이력으로 남긴다.

## 교사 화면

1. **학교 기본계획:** 학교·학년 교육과정 업로드, 추출 결과 수정, 승인본 버전 관리, 학급 적용
2. **교육과정 지도:** 단원, 성취기준, 평가 계획, 미평가 영역
3. **단원 평가 설계:** 성취기준 해석, 과제, 문항, 루브릭, 타당도 점검
4. **루브릭 검토:** 학생 원문과 기준별 근거, AI 추천, 교사 확정
5. **성장 기록:** 피드백, 추가 학습, 재평가, 수준 변화
6. **학기말 종합:** 성취기준별 증거 묶음, 판단 보류, 종합 서술

학생 QR 화면에는 해당 평가 과제와 제출 기능만 표시한다.

## 타당도·신뢰도 안전장치

- 성취기준의 내용과 인지 요구를 문항·루브릭이 실제로 측정하는지 확인한다.
- 말하기 능력이 목표가 아닌 평가에서 말하기 유창성 때문에 사회 개념 수준을 낮추지 않는다.
- OCR·전사 정확도는 학생 성취와 분리하고 원본 확인 기능을 둔다.
- 교사가 경계 수준 사례를 비교할 수 있도록 루브릭 보정 예시를 제공한다.
- 고부담 학기말 판단은 단일 과제나 단일 AI 추천으로 확정하지 않는다.
- 학생·보호자에게 수준 의미, 사용한 증거, 정정 절차를 설명할 수 있어야 한다.

## 구현 단계

1. **설계 스튜디오:** 교육과정·차시 수업안 입력 → 성취기준 해석 → 편집 가능한 루브릭 → 편집 가능한 평가지 → 타당도 검사 → 교사 승인
2. **다중양식 수합:** 글, 비공개 사진 저장과 OCR, 녹음 저장과 전사, 도움 수준이 기록되는 챗봇
3. **설명 가능한 준거 분석:** 기준별 학생 증거 인용, AI 추천·불확실성, 교사 확정, S-W-A-T
4. **학습 처방과 재평가:** 격차별 활동 추천, 실행 기록, 새 맥락 재평가, 변화 비교
5. **학기말 리포트:** 성취기준 히트맵, 성장선, 증거 타임라인, 교사 확정 종합 서술
6. **운영 안전:** 학교별 AI·파일 정책, 비용·속도 제한, 백업·삭제·정정, 모바일·접근성, 보호자 공개

첫 구현 우선순위는 1단계 설계 스튜디오다. 루브릭과 평가지의 품질·버전·교사 승인이 확정되어야 이후 OCR·음성·챗봇 답안을 같은 기준으로 공정하게 분석할 수 있다.

2026-09-01 기준으로 위 구조는 `0002_curriculum_growth.sql`·`0003_ai_assessment_suggestions.sql`·`0004_assessment_growth_bridge.sql`·`0005_school_curriculum_plans.sql`에 구현되어 개발용 Neon에 적용되었다. `/curriculum/setup`에서는 학교·학년 교육과정 PDF·XLSX·CSV·TXT를 외부 AI 전송 없이 추출하고, 교사가 학교 기본사항·단원·성취기준·시수·평가 방법을 검토해 학교별 승인 버전으로 저장한 뒤 학급 학기 계획에 적용한다. 원본 파일 내용은 보존하지 않고 출처 해시와 메타데이터만 남긴다. 실제 교사 화면 `/curriculum`에서는 학기·단원·학생·루브릭뿐 아니라 단원 평가 생성, QR 제출 원본 증거 자동 수합, 평가 맥락, 도움 수준, 기준별 상·중·하 교사 판단, 피드백, 추가 학습, 새 맥락 재평가, 학기말 종합 판단까지 저장하고 조회할 수 있다. AI 추천은 생성 실행·모델·프롬프트 버전·사용량·실패와 완성 추천을 교사 판단과 분리해 보존하도록 준비했다. 교육과정 문항 생성 결과는 영구 저장·동일 요청 재사용·교사별 이력 조회·현재 성취기준과 맞는 초안 복원까지 연결했다. 학생 수행 원문을 외부 AI로 전송하는 호출은 학교의 개인정보 처리 기준과 명시적 승인 전까지 연결하지 않는다. PostgreSQL 통합 테스트는 전체 흐름과 원본 불변성·교사 소유권·중복 방지·독립 증거·AI 이력 규칙을 검증한다. 실제 학생 자료는 넣지 않았다. 운영 전에는 Production/Preview Clerk·Neon 환경 적용, 교사 계정 승인, 실제 로그인 브라우저 저장 E2E가 필요하다.

# Main 병합 후 후속 작업

작성일: 2026-09-08

## 이번 변경의 의미

- 사용자 요청: 수정 코드를 main에 병합하고, 이후 해야 할 일을 Markdown으로 남긴다.
- 포함: `3c9cf47`의 업로드 경계값 수정, 원본과 변환본 연결, 화면 녹화의 전사 경로 차단, 만료 원본 접근 제한 및 기본 OFF 정리 코드.
- 이미 확인한 범위: 합성 PostgreSQL·단위·HTTP 테스트 62개, 별도 오류 재현 검사 7개, ESLint, Next.js 배포용 빌드. 별도 진단 파일은 로컬 outputs에 있고, 주요 회귀 검사는 저장소 tests에 포함되어 있다.
- 이번 병합으로 운영 DB를 변경하거나 학생 자료를 삭제하지 않는다. 운영 로그인·저장소·외부 AI의 전체 흐름을 검증한 것으로 간주하지 않는다.

## P0 — 운영 반영 전에 반드시 수행

### 1. 자동 배포 보류 유지

- [ ] `vercel.json`의 `git.deploymentEnabled.main=false`가 유지되는지 확인한다.
- [ ] GitHub/Vercel에서 이번 main 커밋으로 새 운영 배포가 시작되지 않았는지 확인한다.
- [ ] CLI나 대시보드에서 DB 전환 준비 없이 수동 배포하지 않는다.

이 설정은 main의 Git 기반 자동 배포를 막는다. 다른 브랜치의 미리보기 설정이나 기존 운영 배포를 삭제하지 않는다. 동작 근거: [Vercel Git 설정 공식 문서](https://vercel.com/docs/project-configuration/git-configuration#gitdeploymentenabled).

### 2. DB 변경 창과 복구 계획 확정

- [ ] 연결 대상이 승인된 운영 DB인지 확인한다. 비밀 연결 문자열을 문서·로그에 기록하지 않는다.
- [ ] 백업·복구 가능 시점과 복원 절차를 확인한다.
- [ ] 업로드·OCR/전사·제출 요청을 멈출 운영 수단을 준비한다. 진행 중 요청을 비우고 전환한다. 자동 배포 중지는 학생 쓰기 중지가 아니다.
- [ ] 분리된 테스트 DB에서 기존 데이터 구조를 합성 자료로 재현하고 `0010_evidence_integrity.sql` 이관을 검증한다.
- [ ] 승인된 변경 창에서 `npm run db:migrate`를 실행하고 0001~0010 적용 이력·체크섬을 확인한다. 이미 적용한 마이그레이션을 수정하지 않는다.
- [ ] 복수 원본 때문에 출처를 확정하지 못한 과거 OCR은 자동으로 연결하지 않고 교사 검토 대상으로 남긴다.

구버전 코드와 새 DB 구조를 장기간 함께 운영하지 않는다. 단순히 이전 코드로 되돌리면 새 원본 연결이 누락될 수 있다. 상세 절차: [무결성 수정 적용 안내](EVIDENCE_INTEGRITY_ROLLOUT.md).

### 3. 새 코드 배포와 운영 검증

- [ ] DB 준비 후 같은 변경 창에서 검증한 main 커밋을 배포한다. DB 변경과 새 코드 전환 사이에는 학생 쓰기를 재개하지 않는다.
- [ ] 교사 로그인 → 학급 → 자료 불러오기 → 루브릭·문항 수정 → 교사 승인 → QR 배포를 합성 자료로 검증한다.
- [ ] 학생에게 시험지만 보이는지, 다른 학생·교사 자료에 접근하지 못하는지 확인한다.
- [ ] 사진 A 변환 → 사진 B 재업로드 → A 결과로 제출 불가 → B 변환 후 제출 성공을 확인한다.
- [ ] 음성 녹음·전사와 화면 녹화 제출을 각각 확인한다. 화면 녹화는 전사 API로 보내지 않는다.
- [ ] 챗봇 대화·학습시간·도움 수준, AI 추천·교사 확정·학생 공개 분리를 확인한다.
- [ ] 만료 원본 열람·변환·신규 제출 차단을 확인한다. 실제 원본 삭제로 테스트하지 않는다.
- [ ] 오류율과 저장 결과를 확인하고 학생 쓰기를 재개한다.
- [ ] 운영 전환 성공 후 별도 변경으로 `git.deploymentEnabled.main`을 제거하거나 true로 되돌린다. 이 변경의 푸시부터 자동 배포가 재개됨을 확인한다.
- [ ] 운영 DB 버전, 배포 커밋, 검증 시각과 결과를 OPERATING_STATUS.md에 기록한다.

## P1 — 이번 병합으로 완료되지 않는 검증·개선

| 작업 | 완료 판단 기준 |
| --- | --- |
| 외부 AI 실제 연동 | 학교 승인 OFF에서 전송 차단, ON에서 선택 제공자만 호출, 합성 자료 OCR·전사·챗봇·추천 평가 성공 및 실패 처리 확인 |
| 원본 정리 운영 | 보존 정책·별도 인증키·스케줄러·재시도·삭제 감사 기록 확인 후 별도 승인으로 활성화. 현재 기본 OFF 유지 |
| 개인정보 처리 | 사진·음성의 자동 식별정보 제거는 미구현 범위로 표시하고 검토 절차 확정. 이름·번호 필드 제외만으로 원본 전체 익명화를 보장하지 않음 |
| 학교 승인·설정 위치 | 학교 공통 승인 권한과 교사 권한을 설계하고, 메인의 상세 안전 설정을 적절한 관리 화면으로 이동할지 확정 |
| 결과와 성장 기록 | 시험 점수와 성취기준별 교사 종합 판단의 차이를 사용자에게 설명하고, 추가 학습·독립 재평가·학기말 근거가 실제 운영에서 연결되는지 확인 |
| 학기말 리포트 | 교사 확정 근거만 사용, 비교 가능한 재평가만 성장 계산, 그래프·분석·다음 학습·PDF 출력의 실제 브라우저 검증 |
| 범용 API·백엔드 | 현재 제공자 계약과 구현을 구분. 새 제공자·인증·저장소·배포 환경마다 별도 어댑터 및 통합 검증 필요. 모든 API·백엔드 즉시 호환이라고 안내하지 않음 |

P1은 기존 요구사항과 운영 현황에서 남은 작업을 정리한 것이며, 이번 문서 작성 중 새로 전수 검증한 결과는 아니다.

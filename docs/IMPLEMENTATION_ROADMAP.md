# Mumu 종합 평가 플랫폼 구현 로드맵

최종 정리: 2026-09-04  
범위: 초등 교육과정 기반 준거참조 성장평가

## 1. 최종 완성의 정의

다음 흐름을 실제 교사와 학생 브라우저에서 처음부터 끝까지 수행하고, 모든 결과가 서버에 다시 열리는 상태를 완성으로 본다.

1. 교사가 교육과정·단원 계획·차시 수업안·학습 목표 중 하나를 입력한다.
2. 시스템이 관련 성취기준과 근거 문장을 추천하고 교사가 연결을 확정한다.
3. 관찰 지표·선행 요소·오개념·성공 기준을 바탕으로 루브릭 초안을 만든다.
4. 루브릭을 평가할 문항, 자료, 예상 답안, 배점, 채점 근거를 자동 생성한다.
5. 타당도 검사를 거쳐 교사가 루브릭과 평가지를 수정·승인·잠근다.
6. 특정 학급에 QR·링크로 배포한다.
7. 학생은 글·사진·음성·챗봇 중 허용된 방식으로 답한다.
8. 원본 증거와 OCR·전사·대화 구조화 결과를 함께 보존한다.
9. AI가 기준별 수준·인용 근거·불확실성·격차를 추천한다.
10. 교사가 상·중·하·판단 보류와 피드백을 최종 확정한다.
11. S-W-A-T 학습 처방과 추가 학습·새 맥락 재평가를 연결한다.
12. 학기말에 성취기준별 성장선·히트맵·증거 타임라인·종합 서술을 만든다.

## 2. 변경하지 않을 제품 원칙

- 초등 교육과정만 다룬다.
- 석차가 아니라 성취기준과 비교하는 준거참조 평가를 한다.
- 루브릭을 먼저 만들고, 문항은 루브릭에서 관찰할 증거를 수집하도록 만든다.
- 수준은 상·중·하와 판단 보류를 사용하되, 수준 이름보다 관찰 가능한 수행 기술문을 앞세운다.
- AI는 초안·추천·근거 정리를 담당하고 교사가 최종 승인한다.
- AI 추천에는 반드시 학생 증거 인용과 불확실성을 함께 표시한다.
- OCR·전사 오류는 학생의 성취도와 분리한다.
- 도움받은 수행과 독립 수행을 구분한다.
- 학생 간 등수와 상대평가 그래프를 만들지 않는다.
- 학생 원본, AI 변환본, 교사 보정본, 최종 판단을 서로 덮어쓰지 않고 버전으로 남긴다.

### M0. 현재 운영 흐름 기준선 확정

목표는 새 기능을 쌓기 전에 현재 저장 흐름을 실제 브라우저에서 증명하는 것이다.

구현·점검:

- 승인 교사 로그인
- 테스트 학급과 가명 학생 2명 등록
- 텍스트 평가 생성·공개·학급 배포
- 별도 학생 브라우저에서 저장·최종 제출
- 교사 검토·확정·공개
- 학생 결과 재조회
- Vercel 오류 로그와 Neon 저장 내용 확인

완료 조건:

- 위 흐름이 새로고침과 다른 기기에서도 유지된다.
- 다른 교사·학급·학생이 자료를 열 수 없다.
- 실패 지점과 복구 안내가 화면에 표시된다.

### M1. 교육과정 평가 설계 스튜디오

교사 화면:

- /design 설계 세션 목록
- /design/[sessionId] 7단계 편집 화면
- 단계: 자료 입력 → 성취기준 → 성공 기준 → 루브릭 → 문항 → 타당도 → 승인
- 왼쪽에는 단계, 가운데에는 편집 폼, 오른쪽에는 원문 근거·경고·AI 실행 이력을 둔다.
- 모든 단계는 자동 저장하고 이전 버전을 복원할 수 있게 한다.

입력 형식:

- 1차: 직접 입력, TXT, PDF, DOCX, HWPX
- 기존 HWP 바이너리는 1차에서 PDF 또는 HWPX 변환 안내
- 학교 계획 가져오기 기능의 추출·해시·교사 검토 방식을 재사용

DB 0007_design_studio.sql:

- design_sessions: 교사, 학급/학기/단원, 상태, 현재 단계
- design_sources: 파일 메타데이터, 해시, 추출 상태, 승인된 구조화 맥락
- standard_alignment_candidates: 추천 성취기준, 원문 근거, 신뢰도, 교사 채택 상태
- competency_unpacks: 관찰 지표, 선행 지식·기능, 오개념, 성공 기준, 버전
- assessment_blueprints: 평가 목적, 문항 구성표, 응답 방식, 예상 소요 시간
- validity_audits: 정렬·측정 왜곡·누락·공정성 경고와 해소 상태
- 기존 rubric_versions, rubric_criteria, assessments, ai_question_generation_runs를 연결하고 중복 생성하지 않는다.

API:

- POST/GET /api/teacher/design-sessions
- GET/PATCH /api/teacher/design-sessions/[sessionId]
- POST .../[sessionId]/sources/preview
- POST .../[sessionId]/standards/suggest
- POST .../[sessionId]/competency/unpack
- POST .../[sessionId]/rubric/generate
- POST .../[sessionId]/assessment/generate
- POST .../[sessionId]/validity/audit
- POST .../[sessionId]/approve

AI 출력 계약:

- 자유 문장이 아니라 Zod로 검증하는 구조화 JSON만 허용한다.
- 모델, 프롬프트 버전, 입력 해시, 생성 ID, 토큰, 지연 시간, 성공·실패를 저장한다.
- 같은 입력은 중복 과금하지 않도록 멱등 키와 결과 재사용을 적용한다.
- 성취기준 코드가 원본 목록에 없거나 문항이 루브릭 기준과 연결되지 않으면 저장을 거절한다.
- AI가 실패해도 교사가 수동으로 모든 단계를 완료할 수 있어야 한다.

완료 조건:

- 실제 차시 수업안 한 개로 성취기준 근거부터 루브릭·평가지 초안까지 생성한다.
- 교사가 모든 AI 결과를 수정하고 저장·재접속·복원할 수 있다.
- 각 문항이 성취기준, 루브릭 기준, 기대 증거에 연결된다.
- 해결되지 않은 중대 타당도 경고가 있으면 공개를 막는다.

### M2. 다중양식 학생 증거 수합

DB 0008_multimodal_evidence.sql:

- evidence_assets: 비공개 원본 파일, 소유자, MIME, 크기, 체크섬, 보존 기한
- evidence_derivations: OCR·전사 결과, 도구·모델 버전, 신뢰도, 교사 보정본
- chat_sessions: 평가 목적, 허용된 도움 수준, 시작·종료, 소요 시간
- chat_messages: 발화자, 원문, 힌트 유형, 연결 문항, 순서
- 기존 learning_evidence와 연결

학생 화면:

- 평가에서 허용한 방식만 탭으로 표시
- 글: 문항별 자동 저장
- 사진: 촬영/업로드 → 품질 확인 → OCR 미리보기 → 학생 확인
- 음성: 녹음 → 재생 → 제출 → 전사문 확인
- 챗봇: 한 번에 한 질문, 힌트 제공 여부 기록, 대화 전체 제출
- 학생에게 교사 메뉴·루브릭 내부 판단·다른 학생 정보는 표시하지 않는다.

보안:

- 원본 파일은 공개 URL을 만들지 않는다.
- 교사 소유권과 학생 참여 토큰을 확인한 짧은 수명의 접근만 허용한다.
- 크기·형식·악성 파일 검사와 업로드 제한을 둔다.
- 학교에서 학생 증거의 외부 AI 전송을 허용하지 않으면 OCR·전사를 비활성화하고 원본 수합만 허용한다.

완료 조건:

- 모바일에서 네 방식의 제출과 재접속이 가능하다.
- 원본과 변환본을 나란히 보고 교사가 보정할 수 있다.
- OCR·전사 실패가 학생 수준 하락으로 처리되지 않는다.

### M3. 설명 가능한 AI 준거 분석과 S-W-A-T

분석 순서:

1. 응답을 문항·성취기준·루브릭 기준별로 분리한다.
2. 기준과 일치하는 학생 원문 구절 또는 시간 구간을 인용한다.
3. 상·중·하·판단 보류를 추천한다.
4. 추천 이유, 누락 증거, 상충 증거, 불확실성을 표시한다.
5. 격차를 개념·절차·표현으로 분류한다.
6. S-W-A-T 초안과 학생 친화적 피드백을 만든다.
7. 교사가 수정·확정하며 수정 이유와 감사 이력을 남긴다.

완료 조건:

- 인용 근거가 없는 추천은 저장하지 않는다.
- 증거가 부족하거나 상충하면 자동으로 판단 보류를 제안한다.
- AI 추천과 교사 확정은 별도 필드와 화면에 표시한다.
- 동일한 기준과 예시 답안으로 경계 사례를 반복 평가해 교사 간 보정 자료를 제공한다.

### M4. 맞춤 학습·재평가 루프

- W의 격차 유형과 T의 목표를 바탕으로 짧은 학습 활동 후보를 만든다.
- 교사가 활동을 선택·수정해 학생에게 배정한다.
- 학생의 수행 여부와 반응을 기록한다.
- 기존 문항 반복이 아닌 새 맥락 재평가를 생성한다.
- 이전 증거와 재평가 증거를 같은 기준으로 비교하되 독립 수행 여부를 구분한다.

완료 조건:

- 피드백마다 우선 격차 하나, 실행 활동, 재평가 목표가 연결된다.
- 활동 완료만으로 수준을 올리지 않고 새 독립 증거가 있어야 성장 판단이 가능하다.

### M5. 학기말 성장 리포트

교사용 화면:

- 학급 성취기준 히트맵
- 학생별 성취기준 분포
- 단원·날짜별 성장선
- 글·사진·음성·대화 증거 타임라인
- 미평가·판단 보류·상충 증거 경고
- AI 종합 서술 초안과 교사 확정

학생·보호자용 결과:

- 현재 성취 수준과 그 근거
- 처음과 최근 수행의 변화
- S-W-A-T
- 다음 학기 학습 제안
- 교사 승인 PDF 출력

완료 조건:

- 단순 점수 평균으로 최종 수준을 계산하지 않는다.
- 서로 다른 수행 증거 2개 이상과 독립 증거 1개 이상이 없으면 확정 경고를 표시한다.
- 그래프의 모든 값에서 원본 증거까지 추적할 수 있다.
- 교사 확정 전 리포트를 학생에게 공개할 수 없다.

### M6. 운영 안전과 확대

- 학교별 AI·OCR·전사 사용 여부 설정
- 전체 학생 API와 AI 생성 DB 기반 속도 제한
- 교사·학교별 월 예산과 사용량 대시보드
- 학생 참여 복구, 공용 기기 로그아웃, 기기 변경
- 원본 파일 보존·삭제·정정 정책
- Neon 백업·복원 훈련과 감사 로그
- 모바일, 키보드, 스크린리더, 느린 네트워크 점검
- 파일·API·리포트 부하 시험

파일럿 단계:

- 실명 대신 번호·별칭을 사용하는 테스트 학급
- 3~5명 교사와 소수 학급으로 시작
- 오류율, 교사 수정 시간, AI 제안 채택률, 학생 재평가 성장률을 측정

베타 단계:

- 개인정보 처리와 학교 승인을 완료한 뒤 실제 학생으로 확대
- 월 1,000명 사용량을 기준으로 AI·파일 저장·DB 비용과 속도 제한 검증

## 6. 평가 품질 검사 규칙

### 성취기준 해석

- “이해한다” 대신 식별·설명·비교·적용·평가처럼 관찰 가능한 행동으로 바꾼다.
- 내용 지식과 수행 기능의 선행 요소를 분리한다.
- 실제 수업에서 흔히 나타나는 오개념을 진단 문항과 연결한다.

### 루브릭

- 평가 요소는 서로 독립적이어야 한다.
- “우수/보통/미흡”, “많이/조금”처럼 평가적·양적 표현만으로 수준을 나누지 않는다.
- 인접 수준은 양의 차이가 아니라 추론·근거·전이 같은 질적 차이로 구분한다.
- 학생 자기평가용 쉬운 표현과 교사 보정 메모를 함께 만든다.

### 평가지

- 성취기준의 내용과 인지 수준을 충분히 표집한다.
- 목표가 아닌 읽기·쓰기·말하기·디지털 조작 능력이 결과를 왜곡하는지 검사한다.
- 서술형은 정답 문장 일치가 아니라 핵심 개념·근거·이유·적용을 평가한다.
- 한 문항의 결과만으로 학기말 수준을 확정하지 않는다.

### 학생 분석

- 강점을 먼저 구체적 근거로 제시한다.
- 격차는 개념·절차·표현으로 분류한다.
- “더 공부하기”가 아니라 바로 실행할 수 있는 다음 행동을 제시한다.
- 학생 전체 능력을 단정하지 않고 현재 증거와 성취기준의 관계만 설명한다.

## 9. 바로 시작할 첫 개발 묶음

첫 구현은 M0와 M1의 세로 한 조각으로 제한한다.

1. 현재 텍스트 평가 E2E를 실제 로그인 상태에서 통과시킨다.
2. 0007_design_studio.sql과 도메인 검증을 만든다.
3. /design 목록과 /design/[sessionId] 기본 편집 화면을 만든다.
4. 직접 입력·PDF 수업안 미리보기와 성취기준 근거 연결을 구현한다.
5. Vercel AI Gateway의 비용 효율형 구조화 출력 모델로 역량 풀어쓰기와 루브릭 초안을 만든다.
6. 루브릭을 수정·버전 저장한 뒤 문항 초안을 생성한다.
7. 타당도 경고를 표시하고 교사 승인 후 기존 평가·배포 흐름에 연결한다.
8. DB·API·브라우저 테스트와 운영 배포를 완료한다.

이 묶음이 끝나기 전에는 OCR·음성·챗봇 AI 평가를 동시에 구현하지 않는다. 먼저 공통 평가 기준과 교사 승인 흐름을 안정화해야 모든 응답 방식의 결과를 같은 기준으로 공정하게 다룰 수 있다.

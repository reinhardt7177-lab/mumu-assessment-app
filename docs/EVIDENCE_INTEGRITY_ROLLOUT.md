# 학생 원본·변환본 무결성 수정 적용 안내

## 코드 변경

- multipart 업로드 헤더의 boundary 대소문자를 보존한다.
- 사진·음성만 OCR·전사 처리 대상으로 인정한다. 화면 녹화는 원본을 교사가 직접 검토한다.
- 응답마다 현재 원본 `active_asset_id`, 변환마다 `source_asset_id`를 고정한다. 새 업로드가 현재 답안이며 이전 원본과 변환은 이력으로 남는다.
- 제출은 현재 원본에 연결된 성공 변환만 인정한다. 원본 교체/변환 완료와 제출이 겹치면 내부 `evidence_revision`으로 오래된 검사 결과의 저장을 거절한다.
- 교사 확인본도 화면에서 대조한 원본 ID를 서버에 전달한다. 원본이 달라진 요청은 거절한다.
- 제출 스냅샷에 원본 ID·변환 ID를 남긴다. 제출 후 늦은 성공/실패 콜백은 응답을 다시 열지 않는다.
- 보관 만료/삭제 기록이 있는 원본은 학생·교사 열람, OCR·전사, 새 제출에서 제외한다.

## DB 변경은 먼저 적용해야 함

새 마이그레이션: `db/migrations/0010_evidence_integrity.sql`.

1. 연결 대상과 백업·복원 절차를 운영자가 확인한다.
2. 별도 승인한 운영 변경 창에 `npm run db:migrate`로 0010을 적용한다. 새 코드 배포보다 먼저 적용한다.
3. 구버전 함수는 원본 ID를 쓰지 않으므로, 마이그레이션과 코드 전환 사이에는 업로드/변환/제출을 받지 않는다. 진행 중 요청을 비운 뒤 전환한다. 장기간 구·신 버전을 함께 운영하지 않는다.
4. 새 코드 배포 후 합성 자료로 업로드→변환→제출→교사 확인을 검증한다.

기존 원본은 삭제하지 않는다. 단일 원본이고 변환보다 먼저 존재했던 자료만 기존 변환과 연결한다. 복수 원본의 과거 OCR은 연결을 추측하지 않고 `source_asset_id = NULL`로 보존하며 현재 결과로 자동 사용하지 않는다. 제출된 기록은 교사가 원본을 대조하여 새 확인본을 남길 수 있다. 원본이 이미 만료되었다면 추가 수행 증거를 수집해야 한다.

0010 이후 과거 코드로 단순 롤백하면 원본 연결을 만들지 못한다. 되돌릴 때도 변경 창과 쓰기 중지, 호환 코드 여부를 먼저 검토한다. 기존 마이그레이션이나 기록을 지우는 방식으로 되돌리지 않는다.

## 원본 보관과 삭제

- 보관 만료 즉시 새 코드의 서버 조회에서 차단한다. 저장 당시 `retention_until`을 기준으로 하므로 정책 기간 변경이 기존 파일 기한을 소급 변경하지 않는다.
- 물리 삭제는 별도 작업이며 기본 OFF이다. 이번 개발/합성 테스트에서는 실제 원본을 삭제하지 않았다.
- 범용 스케줄러가 `POST /api/internal/evidence-retention`을 호출할 수 있다. 일반 페이지 방문(GET)으로 삭제하지 않는다.
- 활성화에는 서버 전용 `EVIDENCE_RETENTION_SECRET`(무작위 32자 이상), `EVIDENCE_RETENTION_DELETE_ENABLED=true`, 기존 저장소 자격 증명이 필요하다. 키를 클라이언트·문서·로그에 쓰지 않는다.
- 스케줄러에는 `Authorization: Bearer <서버 전용 비밀키>`를 보안 설정으로 전달한다. 예를 들어 시간 단위로 호출하고 503 실패를 재시도·알림 처리한다. 여기서는 스케줄러를 등록하거나 설정을 켜지 않았다.
- 한 번에 최대 20건을 제한된 시간 안에서 정리한다. 남은 건은 후속 호출에서 처리한다. 다른 경로나 만료 전 원본은 삭제하지 않는다.
- 저장소 삭제 확인 뒤 `evidence_asset_deletions`에 성공 감사 기록을 한 번 남긴다. 실패 시 성공으로 기록하지 않아 다음 호출에서 재시도할 수 있다. 동일 원본의 중복 삭제 요청도 성공 기록은 한 건이다.
- 원본 메타데이터/변환/평가 이력은 이 작업으로 삭제하지 않는다. 이들의 별도 보존 정책을 확정해야 한다.

## 이번 범위 밖

학교 공통 승인 체계, 사진·음성의 자동 개인정보 제거, 메인 설정 화면 이동, 시험 결과와 학기말 판단 통합, 새로운 AI 제공자 어댑터는 이번 네 결함 수정과 별개다. 이 작업을 전체 운영 완료로 안내하지 않는다.

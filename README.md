# Mumu 평가

초등 교사가 학기·단원·성취기준별 평가를 만들고, QR·링크로 모은 학생 수행을 준거 루브릭으로 판단해 피드백·추가 학습·재평가·학기말 종합 결과까지 이어 가는 성장 평가 앱입니다.

> 글·손글씨 OCR·음성 전사·평가 챗봇을 학급별로 운영하는 멀티모달 파일럿 버전입니다. 운영 DB·교사 로그인·학급 명렬·QR 배포·답안 수합·교사 검토는 연결되었습니다. 실제 학생 정보 투입 전에는 로그인 브라우저 전체 흐름, 학교 개인정보 절차와 백업·삭제 정책을 별도로 검증해야 합니다. 세부 상태는 [운영 현황](docs/OPERATING_STATUS.md)에 기록합니다.

## 현재 구현

- 업로드된 2022 개정 교육과정 PDF에서 추출한 초등 6교과 성취기준 423개.
- `/design` 평가 설계 스튜디오: 수업안·교육과정 직접 입력/PDF·TXT·XLSX·CSV 추출 → 공식 성취기준 추천·교사 선택 → 관찰 가능한 성공 기준 → 준거참조 상·중·하 루브릭 → 서술형 평가 문항 → 타당도 감사 → 교사 승인 평가 초안 생성.
- 설계 단계별 수정본과 AI 생성 ID·모델·입출력·토큰·오류를 Neon에 버전 저장하고, 같은 입력은 완료 결과를 재사용. AI 연결이 실패해도 명시적으로 표시된 기본 초안을 수정해 계속 진행.
- 성취기준·루브릭·문항 연결 누락 같은 중대한 타당도 경고는 승인을 차단하며, 점검 후 내용을 바꾸면 재점검을 요구.
- 학교·학년 교육과정 PDF·XLSX·CSV·TXT를 서버 내부에서 읽어 학교 비전·평가 방침·학사 일정과 학년·교과별 단원·성취기준·시수·평가 방법을 검토안으로 생성.
- 교사가 검토한 학교 기본계획을 학년도별 초안/승인 버전으로 보존하고, 승인본의 한 학년·학기·교과 계획을 학급 교육과정으로 원자 적용. 원본 문서 내용은 저장하지 않고 출처 해시와 메타데이터만 보존.
- 기본 정보 → 성취기준 → 평가 문항 → 응답 방법 → 루브릭 → 저장·배포.
- 교사 홈 → 학급 등록 → 학생 명렬 → 공개 평가 선택 → 학급 전용 QR·링크 → 학급별 답안 분석.
- 기존 학급으로 학기 교육과정을 만들면 활성 학생 명렬을 자동 연결하고, 단원 평가 제출을 성장 증거로 수합.
- 학기 → 단원 → 성취기준 → 잠금 루브릭에서 바로 학생용 단원 평가 생성.
- 등록 학생의 QR 제출을 단원 평가 이벤트와 원본 성장 증거에 자동 연결. 재시도·중복 수합 차단.
- 문항 점수로 만든 시험 결과와 여러 증거로 교사가 확정하는 교육과정 성장 수준을 분리.
- 기준별 상·중·하·판단 보류, 피드백, 추가 학습, 독립 재평가, 학기말 종합 판단 이력.
- Neon Postgres 기반 평가·문항·학생 답안·교사 채점·공개 결과·채점 이력 저장.
- Clerk 교사 로그인 + 승인 계정 목록 + 평가별 소유권 검사.
- 학급·평가 조합마다 고유한 QR·링크. 해당 학급의 활성 번호/별칭만 참여하고 자신의 답안만 조회.
- 글 답안 서버 자동 저장·동시 편집 충돌 검출·중복 없는 최종 제출.
- 문항별 글·손글씨 사진·음성·챗봇 응답, private 원본 열람, OCR·전사 교사 확인본, 대화 시간·도움 수준 기록.
- 학교 승인·선택 제공자·학생 식별정보 제거 확인을 서버에서 강제하고, 알려진 이름·번호를 외부 전송 직전에 마스킹.
- 평가 요소별 AI 상·중·하·판단 보류 추천과 근거·불확실성·부족 증거를 교사 판단과 분리 보관.
- 추가 학습→독립 재평가 성장 변화, 학생별 성취 그래프·SWOT·다음 학습·PDF 저장용 학기말 리포트.
- 교사 직접 채점·근거·피드백 저장, 최종 확정과 학생 공개 분리, CSV 내보내기.
- 공급자 중립 `EvidenceAiProvider` 어댑터 + Vercel AI Gateway 구현. 손글씨 OCR·음성 전사·평가 챗봇·평가 요소별 AI 추천 모델을 환경변수로 분리하며, 학교 승인 OFF가 기본입니다. 교사가 선택한 제공자 이외로 자동 전환하지 않습니다.
- 이전 예시 화면은 `/demo`, 예시 시험지는 `/demo/student`. 실제 기록과 섞지 않음.

## 개발 및 운영 준비

Node.js 22.13 이상, npm을 사용합니다. 운영 대상은 사용자가 선택한 기존 Vercel 프로젝트입니다.

1. `.vercel/project.json`의 프로젝트 연결을 확인합니다.
2. Neon과 Clerk를 연결하고 `.env.example`의 필수 변수를 Vercel에 등록합니다.
3. Vercel에서 개발 환경변수를 pull합니다. 기존 `.env.local`의 사용자 정의 변수를 덮어쓰지 않도록 주의합니다. 비밀값은 Git·로그·화면에 노출하지 않습니다.
4. 필수 설정을 확인한 뒤 `npm run db:migrate`로 스키마를 적용합니다. 운영 DB와 테스트 DB를 분리합니다.
5. `npm run dev:vercel`로 개발합니다. 저장소가 없으면 자동으로 데모 DB를 만들지 않으며 실제 제출도 허용하지 않습니다.

```sh
npm install
npm test
npm run lint
npm run build:vercel
```

`npm test`는 테스트 전용 PGlite PostgreSQL에서 실제 SQL을 실행합니다. 운영 Neon 접속을 대신 증명하지는 않습니다. 기본 Sites 개발/빌드 명령은 보존했으며 관련 설명은 [기존 개발 환경](docs/LEGACY_SITES_README.md)에 있습니다.

## 주요 구조

```text
app/                         교사·학생 화면과 권한을 검사하는 API
app/classes/                 학급·공용 명렬·학급별 평가 배포 운영실
app/design/                  7단계 교육과정 평가 설계 스튜디오
lib/assessment-domain.ts     초등 범위·문항·답안·채점 검증
lib/design-studio-domain.ts  성취기준 정렬·성공 기준·루브릭·문항·타당도 검증
lib/classroom-domain.ts      학급·명렬·배포 입력 검증
lib/curriculum-import.ts     PDF·XLSX·CSV·TXT 로컬 추출과 성취기준 연결
lib/school-curriculum-domain.ts 학교 기본계획·승인본·학급 적용 검증
lib/teacher-auth.ts          승인된 교사 계정 검사
lib/evidence-ai/             범용 학생 증거 AI 제공자 계약·Gateway 구현
lib/evidence-storage.ts      private 사진·음성 저장·서명 검사
docs/EVIDENCE_AI_PROVIDERS.md 외부 전송 게이트와 새 제공자 연결 규약
db/migrations/               운영 PostgreSQL 스키마의 기준
db/repository.ts             소유권·참여 토큰·단원 평가·원본 증거 수합 SQL
db/classroom-repository.ts   학급 소유권·명렬·학급별 배포 SQL
db/design-studio-repository.ts 설계 버전·AI 실행 이력·교사 승인 SQL
db/connection.ts             서버 전용 Neon 연결 (로컬 fallback 없음)
data/                        성취기준 데이터와 PDF 추출 보고서
scripts/                     성취기준 추출·운영 마이그레이션
tests/                       영구 저장·격리·동시성·공개·HTTP 검증
docs/OPERATING_STATUS.md     증거가 있는 완료 항목과 미완료 항목
```

운영 전 필수: 실제 로그인부터 결과 공개까지의 브라우저 전체 흐름 검증, 학생 참여 복구·공용 기기 전환, 보존 기한 자동 삭제·백업 복원 절차를 학교 정책에 맞게 확정해야 합니다. 학생 증거 AI 구조와 연결 규약은 [제공자 연결 문서](docs/EVIDENCE_AI_PROVIDERS.md)를 참고하세요.
